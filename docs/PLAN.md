# План хакатона — часть «Дизайн-система Ростелекома на Svelte» (rt-ui)

> Статус на 20.09.2026. Это самостоятельная часть проекта со своей целью, метриками и блоком в презентации.
> Она заменяет вариант A из §12 `dop.md` («токены + свои компоненты на headless-базе») более сильным решением:
> **полный порт дизайн-системы с машинной проверкой совпадения с эталоном**.

## 1. Зачем отдельной частью

* В хакатоне есть отдельный критерий дизайнеров: максимально точное соответствие **новой** дизайн-системе Ростелекома (gen2).
  Готовой реализации под Svelte нет, публичный Storybook закрыт для автоматического доступа.
* Фронт CRM пишется на SvelteKit, и таблиц в нём будет много: без надёжной библиотеки компонентов (прежде всего таблицы) каждый экран
  превращается в ручную вёрстку.
* Актуальные React/Vue-версии дизайн-системы организаторы участникам не выдают (внутренняя разработка Ростелекома, дорогой актив). Мы работаем только по публичным
  материалам и **не открываем результат всем**, но для кейсодержателей это бесплатный шаг в новый фреймворк (см. `DESIGN-SYSTEM-PORT.md`, раздел «Для кейсодержателя»).
* Результат ценен сам по себе: это переиспользуемая библиотека, а способ её создания (эталон → сверка → порт) — воспроизводимая инженерная практика,
  которую можно показать жюри.

## 5. Риски и как они закрыты

| Риск | Митигация |
|---|---|
| Эталон закрыт WAF для скриптов | работали только через обычный браузер пользователя (расширение Chrome), статику сохранили локально; обход защиты не применялся |
| «Похоже на глаз» вместо совпадения | приёмка только машиной: DOM + боксы + пиксели с допуском 0 |
| Нестабильность самого эталона (перерисовка антиалиасинга, гонки шрифтов) | детерминизм окружения (время, `Math.random`, шрифты, заморозка анимаций) + многократные снимки и принятие любого из собственных вариантов эталона + отдельный уровень «AA-only» (не более 12 краевых пикселей); всё видно в отчёте, `--exact` отключает допуск |
| Права на дизайн-систему и «утечка» внутреннего актива | репозиторий закрытый; работа только по публичным материалам, без обхода защиты и без внутренних пакетов; условия передачи согласуем с кейсодержателем |
| Лицензия шрифта Rostelecom Basis | файлы шрифта не коммитятся (`.gitignore`), подключаются локально; в публичном репозитории — только `@font-face` и инструкция |
| Регрессии при параллельной работе | независимый верификатор на группу + свип всех историй; так были найдены и исправлены 2 общих дефекта (порядок порталов, слушатели `usePopper`) |
| Расхождение поведения и картинки | поведение сверяется интерактивными сценариями (клавиатура, открытие/закрытие, выбор), а не только статикой |

## 6. Связь с планом CRM (`dop.md` §9, §12–13)

* Токены и слой компонентов идут в шаг 1 параллельно с каркасом — этот трек выполнен раньше срока и не блокирует фронт.
* Для CRM готово: кнопки и формы, `Select`, `Modal`, `Popover`, `Tooltip`, `DropdownMenu`, `Pagination`, **`TableGrid`**.
  Экраны из спецификации (список организаций, сделки, каталоги) собираются из них без ручной вёрстки.
* Формулировка для защиты (заменяет §12.7): «Мы не подключали второй фреймворк, а воспроизвели дизайн-систему нативно на Svelte и
  **доказали** совпадение с эталоном автоматической сверкой DOM, геометрии и пикселей на всех историях и во всех темах».
